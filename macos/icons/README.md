# macOS app icons

The Near.ai app's icon, as Icon Composer documents. Each `.icon` is a
directory (`icon.json` plus `Assets/`) that opens in Icon Composer by
double-click; `scripts/make-icon-document.sh` compiles the channel's document
into the bundle with `actool`.

| Document | Channel | Contents |
| --- | --- | --- |
| `production/AppIcon.icon` | production | The NEAR AI tile: the "N" on the brand-tile ground |
| `staging/AppIcon.icon` | staging | The same tile plus an amber hazard ribbon across the top-right corner |

`macos/channels/<channel>.env` names the document in `TC_ICON_SOURCE`.

## How the icon is built

It follows Apple's [app icon guidance](https://developer.apple.com/design/human-interface-guidelines/app-icons)
and the NEAR AI brand book's rule for app icons (`docs/guidelines/08-iconography.md`
in the design system): build from the tile, with the background as a fill and
the N as the foreground layer, never the tile file itself, whose rounded
rectangle is already masked.

- **Background**: an Icon Composer solid fill, not an image. Default is
  `brand-tile` #0B8FF6; dark is #024175, the NEAR blue at the brand hue
  stepped down for dark mode. Apple and the brand book both prefer a coloured
  ground in dark mode over black.
- **Foreground**: `Assets/near-n.svg`, the kit's N path verbatim
  (`nearai_logo_kit/Tertiary/01_Color/tile-color.svg`), in `brand-paper`
  #F3F3F2, on an unmasked 1024 x 1024 square at the kit's own proportion
  (the N is 58.5% of the tile's width, centred). Plain sRGB hex, which Icon
  Composer reads as sRGB.
- **Glass**: the system's. One group, default neutral shadow, translucency
  0.25 so the N stays close to paper while still taking the Liquid Glass
  highlights. No effects are baked into the artwork.
- **Appearances**: default and dark are specified; clear (light and dark)
  and tinted (light and dark) are generated by the system from the near-white
  N, which is what the guidance asks for (one prominent white element).
- **Staging ribbon**: `Assets/staging-ribbon.svg`, its own top group so the N
  never covers it. Amber #FFB000 with thin ink #14110A stripes; the stripes are
  kept thin so the ribbon still reads as amber at 32px. It runs past the
  canvas edge and the system mask trims it.

The staging document carries its own copy of `near-n.svg`, because a `.icon`
has to be self-contained; the build refuses a copy that differs from
production's.

## What the build checks

`actool` validates nothing in `icon.json`, so a typo yields a different icon,
not a failed build. `make-icon-document.sh` therefore:

1. checks the document (`scripts/verify-icon-document.py`): every layer's file
   exists and every file is a layer, base and dark fills both set and
   different, no text or raster in the SVGs, the kit's N path, the ribbon on
   staging only and on top;
2. compiles it at the app's deployment floor (macOS 14.0);
3. decodes the fallback `.icns` (`scripts/verify-icon.swift`): a blue tile, an
   N of the right size in both halves and through the middle, and amber in
   the top-right corner on staging and nowhere on production;
4. reads `Assets.car` (`scripts/verify-icon-appearances.py`): light, dark and
   tintable compositions, each ground equal to the document's fill, the
   declared layers and no others, and pre-rendered images from 16 to 1024
   for macOS 14 and 15.

## Previewing every appearance

Icon Composer shows all of them. Headless, its `ictool` renders one at a time
(note `xcrun ictool` is a different tool):

```bash
"/Applications/Xcode.app/Contents/Applications/Icon Composer.app/Contents/Executables/ictool" \
  macos/icons/production/AppIcon.icon --export-image --output-file dark.png \
  --platform macOS --rendition Dark --width 1024 --height 1024 --scale 1
```

Renditions are `Default`, `Dark`, `ClearLight`, `ClearDark`, `TintedLight` and
`TintedDark`; `--design-generation 26` renders as macOS 26 does.
