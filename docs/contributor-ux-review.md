# Contributor App UX Review — Trust by Default

I tried the Trace Commons contributor app from the perspective of someone who wants to
contribute regularly and earn credits, but does not want managing those contributions to
become another ongoing task.

My main reaction was that the app currently asks the user to make too many decisions.

The experience I would prefer is much simpler:

Set it up once, trust that Trace Commons is protecting my privacy, and let contributions
happen in the background.

I absolutely want the ability to exclude a particular conversation, project, or source when
I choose to. But I would prefer that to be the exception rather than something I have to
actively decide for every contribution.

## The core issue: too much ongoing attention

Today, contributing feels like something I need to supervise.

During onboarding I am asked to make several choices about what to watch and how
contribution should work. After setup, the app continues to put decisions in front of me
about individual traces or projects.

That gives me control, but it also creates cognitive overhead.

As a user, I do not really want to become the privacy filter myself. I want to understand
and consent to the privacy model once, then trust the app to apply it.

The ideal mental model for me would be:

Connect → consent → contribute automatically → earn credits.

After that, I should only need to open the app when I want to check activity, change
something, pause contribution, or exclude specific content.

## Privacy should enable automation

The strongest reason I would be comfortable with automatic contribution is that Trace
Commons already has a privacy layer: content is scrubbed locally before it is sent.

That should be a major part of the product promise.

Instead of asking me to repeatedly decide whether something is safe to contribute, I would
rather the product say, in effect:

> "We remove private information before anything leaves your machine. Contributions happen
> automatically unless you tell us otherwise."

That is a much more compelling experience.

Of course, users who want to review every contribution should still be able to do so. But I
would make that an optional high-control mode rather than the default experience for
everyone.

## Make exclusion easy, not approval mandatory

I would still want a simple way to say:

- don't contribute this conversation;
- don't contribute this project;
- pause contributions temporarily;
- let me review before submitting from this source.

Those controls are valuable.

The distinction is that I want to exclude selectively, rather than approve continuously.

By default, I would be comfortable sharing eligible content if I can trust that personally
identifying or otherwise private information has been removed first.

## Onboarding should establish that trust

The current onboarding asks the user to make a number of decisions before contribution
really gets going.

I would simplify onboarding around two things:

1. Connect my account / data source.
2. Explain the privacy guarantee clearly and get my consent.

At that point, contribution can begin with sensible defaults.

Folder selection, project-level modes, timing controls, upload limits, and other
configuration can still exist, but most of them feel more appropriate as advanced settings
than decisions every new user needs to make.

The best onboarding outcome would be that I finish setup thinking:

> "Great. It is running, my private information is protected, and I don't need to think
> about it again."

## Credits should reinforce the value exchange

The credits are also important to this experience.

If I am contributing useful data to the commons and receiving credits in return, I want that
value exchange to be easy to understand.

The app should make it obvious that contributions are happening and that I am earning credit
for them, without requiring me to repeatedly approve each contribution.

For example, I would much rather occasionally see:

> "12 conversations contributed. Privacy filtering complete. Credits pending."

than repeatedly be asked whether each individual trace should be submitted.

This makes contributing feel rewarding rather than administrative.

## Recommended default

My preferred default would therefore be:

Automatic contribution with privacy protection on by default.

The user consents once during setup. Trace Commons automatically scrubs eligible content
locally and contributes it. The user can see what has been contributed, exclude individual
conversations or projects, pause at any time, or switch into a review-everything mode if
they want more control.

That preserves user agency without requiring constant user attention.

## Bottom line

The current product gives users a lot of control, but it also makes the user responsible for
too much of the ongoing decision-making.

For me, the more attractive product is one I can trust rather than supervise.

I want to set it up, understand what privacy protections are being applied, give my consent,
and then let Trace Commons do the work in the background while I earn credits.

Give me the ability to intervene when I want to — but don't require me to intervene for the
system to work.
