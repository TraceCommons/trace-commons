# Codex comparison source profile v1

Status: implemented structural admission rule; private pilot and model-performance claims remain unqualified.

The `codex-rust-v0.154.0-task-records-v1` rule recognizes a bounded set of records emitted by Codex Rust 0.154.0 at upstream revision `6b9826e3aa83b1a5947db50f4332cb9c65f1b340`. It derives recorded model declarations and source/session/turn bindings. It does not establish which provider served a request, exclusive model use, independent work items, or verified outcomes. Codex source is used to generate development fixtures; it is not a Trace Commons runtime dependency.

## Supported evidence

This first rule requires the recorded session metadata `cli_version = 0.154.0`, `originator = codex_cli_rs`, `source = exec`, and `history_mode = legacy`. Base instructions must carry either the supported `custom` provenance shape or `model` provenance whose declared model exactly matches every qualified turn and world-state model. The default-instruction variant has its own reproducible released-writer fixture. Other provenance shapes and interactive/editor origins are not admitted merely because their version number matches. Their generic imports may still succeed, with comparison attribution unavailable.

| Case | Admission boundary |
| --- | --- |
| Direct messages | Complete supported lifecycle, consistent model/context/configuration, and matching identities are required. |
| Reasoning records | Supported record shape and position are checked; private reasoning text is not retained in derived attribution. |
| Sequential `exec_command` calls and outputs | Matching call/output records and supported lifecycle are required. Custom tools and parallel calls remain unsupported. |
| Multiple turns | Turns remain attempts/evidence within the user-reviewed task. More turns never create additional comparison trials. |
| Optional usage | Invalid usage remains invalid even if a later record is valid. Missing or invalid optional usage does not by itself discard otherwise supported model attribution. |
| Forks, delegation, mixed models, and conflicting context | Typed exclusions; no fallback to a final model label. |
| Other source versions or record shapes | Attribution is unavailable. Generic Codex import remains available when its existing parser accepts the input. |

The fixture [manifest](../../../crates/trace-commons-contributor/fixtures/insights/codex-task-attribution/manifest-release-0.154.0.json) pins the exact generated bytes and generator. The older `c4017a87` writer-fixture profile stays fixture-only and cannot admit production comparison cohorts. The released fixtures were generated with synthetic responses and deterministic sanitization; their timing, outcomes, model labels, and tool success are test inputs, not real-user measurements.

## Persistence and independent-task review

Store v9 persists attribution bound to the saved source digest. Comparison-task episode bindings freeze sorted hashed session identities. Overlap uses those frozen identities as well as canonical snapshot identity, so different-byte exports of one session remain connected after a source snapshot is deleted. Deleting a snapshot does not free another export to count as an independent task.

A task can use current attribution only when its frozen bindings include the corresponding session identity. Legacy tasks with empty frozen identities remain unqualified after an identical-byte reimport upgrades source attribution. An explicit binding refresh and independence review are required; refreshed same-session tasks still overlap. No migration silently asserts independence.

Source admission is only one eligibility condition. The task must also have complete matching context, current evidence/outcome bindings, a current user independence confirmation, appropriate cutoff chronology, and no overlapping task evidence. Outcomes remain categorical user reports. The comparison engine still has no calibrated advantage estimator, and observed token aggregation remains separately qualified.

## Verification boundary

Regression coverage includes source/profile exclusions, sequential tool/reasoning records, optional-usage status, generic import compatibility, persisted source binding, legacy reimport, retained overlap after deletion, and specification projection. An independent CLI workflow imports the two direct fixtures, creates two reviewed tasks, verifies nonempty cohort counts, and checks duplicate-session exclusion after deletion. This establishes synthetic end-to-end wiring; a private pilot on authorized real tasks remains an explicit delivery gate.
