## Global Constraints

- Preserve the primary checkout and Kristi's client/daemon ownership.
- Invites grant full trust to the NEAR account, with no contribution volume limits. Do not implement the older invite-keyed cap proposal.
- No blanket disarm of existing armed folders. Non-invite accounts retain armed folders under server-side trust limits.
- Everyone uses a NEAR account; redeeming an invite must eventually elevate that identity rather than create another tenant.
- Folder consent never implies inference provenance. A receipt attests the final exchange only.
- Preserve per-contribution admission until an authenticated replacement is implemented and tested; never remove the namespace check as an interim shortcut.
- Shared client contracts stay MIT/Apache. Server files retain AGPL headers. Logs and audits remain hash-only or label-only.
- No deployment, release, or automatic-contribution enablement is part of this starting slice.

2. Exact membership must reject unknown suffixes, case changes, whitespace and appended server-pass versions.
3. Classifier failure must not yield a signed artifact through the witness's real full-pipeline path.
4. Error propagation must retain permanent versus transient classification.
5. Successful sidecar redaction must remain usable; this change must not make every sidecar call fail.
