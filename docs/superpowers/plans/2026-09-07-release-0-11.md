# Release 0.11 Plan

> **For agentic workers:** steps use checkbox (`- [ ]`) syntax for tracking.
> Read the whole document before starting. The ordering constraints are the
> point; several steps fail silently if taken out of turn.

**Goal:** Ship 0.11 — the release the 0.10 gate was held open for.

**What 0.11 is:** answering model calls became a top-level destination that
lists the coding tools on the machine and connects them one at a time behind a
preview. 0.10 could tell a contributor the feature was on; 0.11 can tell them
whether anything is using it.

**Spec/plan lineage:** `2026-09-07-private-inference-top-level-design.md`,
`2026-09-07-harness-routing-design.md`, and their plans.

## Step 4 — Tag, in this order

**Push the contributor tag FIRST and wait for its release to exist.** Do not
push both in one command.

`publish-updates` builds `latest.json` by `curl`ing the `contributor-v<version>`
release assets, and **a failed curl is deliberately non-fatal** — the slug is
silently omitted. At 0.9.0 the contributor release finished 107 seconds before
`latest.json` was written. If the app tag runs ahead, a *signed* manifest naming
zero CLI platforms is published, every installed CLI stops seeing updates, and
**no job goes red.**

```bash
git tag contributor-v0.11.0
git push origin contributor-v0.11.0

until gh release view contributor-v0.11.0 --repo TraceCommons/trace-commons \
        --json assets --jq '.assets | length' 2>/dev/null | grep -qE '^[1-9]'; do
  sleep 30
done

git tag app-v0.11.0
git push origin app-v0.11.0
```

- [ ] Contributor tag pushed, release has assets
- [ ] App tag pushed
- [ ] Both workflows watched to completion

## Known limits shipping in 0.11

State these rather than discovering them in a bug report:

- **Two harnesses, not four.** Gemini cannot be described — a catalog entry's
  value is a facade URL, exactly two facades exist, and neither is Gemini's wire
  shape. Cline has no known provider-config file.
- **The compiled-in catalog is empty**, deliberately: it is a value we own that
  a one-line edit extends, rather than upstream's `Catalog::default()` which is
  pinned empty forever.
- **The WinUI binding layer is only proven by CI.** It does not compile on a
  macOS host, so XAML bindings and converters are verified by the `windows
  contributor app` job and nowhere else.
