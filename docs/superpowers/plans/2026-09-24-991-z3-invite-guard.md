# #991 Z3 Reserved Invite Namespace Guard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refuse any newly created or imported fixed-mode invite whose tenant ID claims a reserved NEAR account namespace.

**Architecture:** Put one pure namespace predicate in the AGPL invite registry module. Apply it before either admin creation or file import writes to PostgreSQL, preserving the current import's partial-progress reporting and all existing invite redemption behavior. This is an immediate namespace guard, independent of the later account-based invite redemption work in Z9/Z6/Z7.

**Tech Stack:** Rust, Axum, existing PostgreSQL invite registry. No new dependencies or migration.

**Spec:** `docs/superpowers/plans/2026-09-24-991-zaki-server.md` (Z3 and global constraints); `docs/superpowers/specs/2026-09-23-connect-and-forget-consent-design.md` (R3 namespace discussion); `crates/trace-commons-server/src/bin/trace_commons_ingest_internal/admission.rs` (`ANCHOR_NAMESPACES`).

## Global Constraints

- `near-` and `nearai-` are reserved for provisioned account tenants. A fixed invite must not acquire either prefix. Match the prefix case-insensitively so case folding elsewhere cannot make a stored invite collide later; do not require a valid 64-hex suffix to reject a claim.
- Keep valid existing fixed tenant IDs byte-for-byte and leave derived-mode invite templates and redemption unchanged. Do not silently rewrite existing database rows.
- Preserve the file import's idempotency and partial-summary error format. Errors may name an entry number and fixed public label, never invite code, subject hash, or tenant ID.
- Every added server `.rs` file needs the AGPL header; this plan adds none. No dependency changes; no license allowlist edits.
- The eventual account-based invite grant must elevate an authenticated NEAR identity; this guard does not implement that grant or change admission enforcement.

## Review Focus

1. A reserved prefix with malformed, empty, or mixed-case suffix must still be refused before insertion.
2. `nearby-*` and `nearaiX-*` are ordinary IDs and must remain accepted.
3. A reserved entry after valid import entries must report already imported counts without leaking IDs.
4. A rejected admin request must not mint a code, write a grant, or update the registry cache.
5. Derived-mode templates must retain current behavior; this fixed-mode guard must not silently change them.

### Task 1: Define and pin the fixed-tenant namespace predicate

**Files:**

**Interfaces:**

Include an exact `near-` and `nearai-` result so no suffix validation can weaken this guard.
- [x] **Step 2: Run** `RUSTFLAGS='-D warnings' cargo test -p trace-commons-server --lib fixed_invite_tenant_uses_reserved_namespace`; expect a missing-function failure.
- [x] **Step 3: Implement** the pure predicate adjacent to `InviteTenantMode` using an ASCII case-insensitive prefix check over the shared reserved-prefix constant. Admission uses that same constant. Leave all storage and redemption paths unchanged.

  ```rust
  pub const RESERVED_ACCOUNT_TENANT_PREFIXES: [&str; 2] = ["near-", "nearai-"];

  pub fn fixed_invite_tenant_uses_reserved_namespace(tenant_id: &str) -> bool {
      RESERVED_ACCOUNT_TENANT_PREFIXES.iter().any(|prefix| {
          tenant_id
              .get(..prefix.len())
              .is_some_and(|head| head.eq_ignore_ascii_case(prefix))
      })
  }
  ```
- [x] **Step 4: Re-run** the focused test; expect pass. Commit this independently if task reviews are separate.
