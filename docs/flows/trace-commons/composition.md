# Composition correspondence

This table relates the standalone [abstract composition](models/end_to_end.md)
to detailed domain boundaries at source baseline
`8218cc8ae408eb9c2c8a16d5768d9f6e0f7f83d6`. It is a manually reviewed
projection specification, not executable synchronization or a refinement
proof. Domain simulations/typechecks do not establish this composition; a
composition simulation does not establish the detailed models or source.
All names below are module-local. `t` denotes
`end_to_end.s.traces.get(i)`, `r` a detailed run, `e` a client queue entry.
Finite integer identities are related through the row's stated mapping,
not by assuming every module uses the same numeric encoding.

## Durable verdict versus processing status

The composition stores `submissionStatus` independently from `runState` and
`phase`, matching `server_pipeline.s.runs[id].submissionStatus`. Receipt
Admission initializes it; privacy escalation and Review commit update it;
withdrawal stamps revoked. Generic retry exhaustion remains possible for a withdrawn Settle run and
rejects only a live received submission (`versioned_pipeline.rs:8034`); accepted/quarantined
verdicts remain unchanged. The separate privacy-classification-failure
exception is owned by the detailed pipeline and is not represented as generic
composition exhaustion. `serverStatus` projects this stored verdict, never
labels all failed Score/Settle runs rejected or all human holds quarantined.
App history still observes only a later daemon poll and IPC result.

### Composition limits

This document does not connect Quint state variables at runtime. Each detailed
model's initial environment may begin before or after the composition
boundary. For example, receipt principal IDs, contribution account labels,
lifecycle object ownership and settlement leg IDs require the explicit
semantic relation above; raw integer equality would be wrong. A future
executable composition must choose and enforce one relation, synchronize
boundary events and account for each permitted detailed stutter. Merely
importing these models or matching action names would not do that work.

The composition represents one tenant, manual preview/approval, versioned
processing and representative payout lines. Domain-only behavior includes
legacy receipts, containment, all first-run screens, managed inference/tools,
Insights/learning/publication, exports, configured optional routes and exact
cross-platform shells. These are not claimed absent from the product. The
coverage inventory and domain notes identify their owners and remaining gaps.
No owner-selected product promise has been encoded or checked.
